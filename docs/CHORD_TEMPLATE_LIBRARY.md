# ModeCalc — 自定义和弦模板库设计文档

## 1. 背景

### 1.1 为什么不用第三方库

| 库 | 问题 |
|----|------|
| **pychord** | `find_chords_from_notes()` 不支持缺音匹配。C E Bb F# (缺 5th G) 无法识别为 C7#11。返回 `[]` |
| **chordie** | Node.js 库，马尔可夫链和弦进行预测器，非 pitch class → 和弦名识别器 |
| **music21** | ~200 MB，太重 |

结论：必须自建和弦模板库。

### 1.2 设计目标

- 输入任意 MIDI note set → 输出最佳匹配和弦名
- 支持 jazz voicing（允许缺 5th、部分缺音）
- 多候选消歧：完整度 > 原位 > 简单度
- Jazz 速记命名，与现有风格一致
- 模板数量 ~80，覆盖三和弦到十三和弦 + altered dominants

## 2. 设计决策

| 决策点 | 结论 | 理由 |
|--------|------|------|
| 命名风格 | Jazz 速记（C-, C-7, Cø, C△7…） | 保持现有代码风格，目标用户为 jazz musician |
| 模板范围 | ~80 种 | 覆盖标准 jazz 和弦语汇 |
| 子集匹配 | 输入 PC ⊆ 模板 PC | 允许缺 5th / voicing 不完整 |
| 单音/音程 | 保持现有逻辑 | 无歧义，不需模板 |
| 三和弦转位 | 全部 slash（C/E, C/G） | 避免歧义 |
| 4 PC 上限 | 移除 | 5-7 音走模板匹配 |
| 消歧优先级 | 完整度 → 原位 → 简单度 | 见 §4 |

## 4. 消歧算法

### 4.1 匹配函数 `_match_all(notes: set[int], pcs: list[int]) -> dict`

```
matches = []

for root_pc in 0..11:
    for (intervals, suffix) in CHORD_TEMPLATES:
        shifted = {(root_pc + i) % 12 for i in intervals}
        if pcs ⊆ shifted:
            missing = len(intervals) - len(pcs)
            bass_pc = min(notes) % 12
            inversion = 0 if bass_pc == root_pc else 1
            matches.append({
                name: PITCH_NAMES[root_pc] + suffix (+ "/bass" if inversion),
                missing,      # 缺音数
                inversion,     # 0=原位 1=slash
                template_size, # 模板总音数
            })

# 排序: missing ASC → inversion ASC → template_size ASC
matches.sort(key=lambda m: (m.missing, m.inversion, m.template_size))
return matches[0] if matches else unknown
```

### 4.2 消歧示例

**C E G Bb D (5 PC):**

| 候选 | missing | inversion | size | 排序 |
|------|---------|-----------|------|------|
| C9 [0,4,7,10,2] | 0 | 0 | 5 | **1st** ✓ |
| C7 [0,4,7,10] | 1 | 0 | 4 | 2nd |
| C11 [0,4,7,10,2,5] | 1 | 0 | 6 | 3rd |

→ 选 C9（完整匹配优先）

**C E Bb F# (4 PC, 缺 5th):**

| 候选 | missing | inversion | size | 排序 |
|------|---------|-----------|------|------|
| C7#11 [0,4,7,10,6] | 1 | 0 | 5 | **1st** ✓ |
| C7b5b9 [0,4,6,10,1] — F#(=6) 在模板中，但 D#(=3) 不在… | | | | |

→ 选 C7#11（缺音 1 = 5th 缺失，逻辑正确）

### 4.3 算法复杂度

12 根音 × 60 模板 × 7 音比较 = ~5000 次 set 操作。MIDI 实时输入完全无压力。

## 5. 代码变更

### 5.1 `chord_engine.py`

**移除：**
- `TRIAD_TEMPLATES`, `SEVENTH_TEMPLATES`, `CHORD_TEMPLATES`
- `_match_chord()`, `_match_subset()`, `_build_slash_chord()`

**新增：**
- `CHORD_TEMPLATES: list[tuple[tuple[int,...], str]]` — 60 种模板

**保留：**
- `recognize()`, `note_info()`, `INTERVAL_NAMES`
- `_pick_best_match()` — 可移除，新逻辑在 `_match_all` 内部排序
